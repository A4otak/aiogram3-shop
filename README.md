# 🛒 Telegram-бот: магазин цифровых товаров

Готовый Telegram-бот для продажи цифровых товаров (аккаунты, ключи, коды, ссылки и т. д.) с автоматической выдачей после оплаты. Оплата принимается через **CryptoBot** (цены в рублях) или с внутреннего баланса. Всё управление — прямо в Telegram, через админ-панель.

Написан на **Python 3.11+**, **aiogram 3**, **aiosqlite** (SQLite) и **aiohttp**. Отдельный сервер, веб-сайт и открытые порты не нужны: бот работает через long polling и запускается на обычном компьютере или VPS.

## Возможности

### Для покупателя

- 🛍 **Каталог** с категориями и товарами. У каждой категории и товара виден остаток («🟢 Аккаунты · 12 шт.»). Списки разбиты на страницы по 5 записей.
- 🔢 **Выбор количества**: кнопки `1 шт.`, `2 шт.`, `5 шт.`, `✏️ Своё количество` и `📦 Купить всё`.
- 🧾 **Подтверждение покупки** с названием товара, категорией, ценой и итоговой суммой.
- 💳 **Оплата через CryptoBot**: бот создаёт счёт в рублях, а CryptoBot сам пересчитывает его в выбранную покупателем криптовалюту.
- 💰 **Оплата с баланса** одним нажатием, если денег хватает.
- 📦 **Мгновенная выдача**: данные приходят в сообщении и отдельным файлом `order_<номер>.txt`.
- 👤 **Профиль**: ID, баланс, число заказов и потраченная сумма.
- 💳 **Пополнение баланса** через CryptoBot (суммы 100, 300, 500, 1000 ₽ или своя от 50 до 50 000 ₽).
- 📜 **История покупок**: все заказы, данные можно открыть и скачать заново в любой момент.
- ❓ **Помощь** с инструкцией и кнопкой «Написать в поддержку».

### Для администратора

- ➕ **Добавление категорий.**
- 📦 **Добавление товаров**: можно создать новый товар или **пополнить существующий** (даже если он уже полностью распродан). Содержимое вставляется текстом или загружается `.txt`-файлом.
- 🔐 **Настройка CryptoBot** прямо из бота: токен проверяется при сохранении.
- 📊 **Статистика**: число пользователей, продажи, выручка (отдельно через CryptoBot и с баланса), итоги за 24 часа, пополнения баланса, остатки на складе.
- 💰 **Управление балансом пользователя**: выдать или забрать деньги с подтверждением. Пользователь получает уведомление. Здесь же — постраничная история платежей пользователя (заказы и пополнения со статусами), чтобы разобрать случай «деньги ушли, а товара нет».
- 🏠 **Кнопка «В меню магазина»** — вернуться в режим обычного покупателя.
- ⬅️ На каждом шаге диалога есть кнопка «Назад» (на один шаг назад, а не в самое начало).

## Команды и кнопки

| Команда | Кто может | Что делает |
|---|---|---|
| `/start` | Все | Регистрирует пользователя, включает нижние кнопки и показывает главное меню |
| `/help` | Все | Инструкция по покупке и кнопка «Написать в поддержку» |
| `/admin` | Только администраторы из `ADMIN_IDS` | Открывает админ-панель |

Остальным пользователям команда `/admin` просто не отвечает.

**Нижние кнопки** (появляются после `/start`): `🛍 Каталог`, `👤 Профиль`, `❓ Помощь`. Те же разделы есть в инлайн-меню под приветствием. Все остальные действия выполняются кнопками под сообщениями — никаких команд запоминать не нужно.

> 💡 **Совет:** чтобы команды появились в меню «/» в Telegram, откройте [@BotFather](https://t.me/BotFather) → `/setcommands` → выберите бота и отправьте:
> ```
> start - Главное меню
> help - Помощь и поддержка
> ```
> Команду `/admin` в этот список лучше не добавлять, чтобы покупатели её не видели.

## Что нужно перед началом

1. **Python 3.11 или новее** (проверено на 3.12 и 3.13).
2. **Аккаунт Telegram**, чтобы создать бота.
3. **Токен бота** от @BotFather (подробности [ниже](#настройка-env-все-переменные)).
4. *(Для приёма оплаты)* **Токен CryptoBot**. Без него магазин запустится и каталог будет работать, но оплатить через CryptoBot будет нельзя.

## Установка и запуск на Windows

### 1. Установите Python

1. Скачайте установщик с [python.org/downloads](https://www.python.org/downloads/).
2. Запустите его и **обязательно поставьте галочку «Add python.exe to PATH»** внизу первого окна, затем нажмите *Install Now*.
3. Откройте **PowerShell** (правый клик по «Пуск» → «Терминал» или «Windows PowerShell») и проверьте:
   ```powershell
   python --version
   ```
   Должно вывести `Python 3.11.x` или выше.

### 2. Скачайте проект

Распакуйте архив проекта (или склонируйте репозиторий) в любую папку, например `C:\bots\tg_bot`, и перейдите в неё:

```powershell
cd C:\bots\tg_bot
```

### 3. Создайте виртуальное окружение и установите зависимости

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> Если PowerShell пишет «выполнение скриптов отключено», выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, подтвердите `Y` и повторите активацию. Либо используйте обычную командную строку (`cmd`) и команду `.venv\Scripts\activate.bat`.

После активации в начале строки появится `(.venv)`.

### 4. Создайте файл `.env`

```powershell
copy .env.example .env
notepad .env
```

Заполните значения (см. [таблицу переменных](#настройка-env-все-переменные)), сохраните файл и закройте блокнот.

> ⚠️ **Частая ошибка:** Windows может скрывать расширения файлов, и файл превратится в `.env.txt`. Включите в Проводнике «Вид → Показать → Расширения имён файлов» и убедитесь, что файл называется именно `.env`.

### 5. Запустите бота

```powershell
python main.py
```

В консоли появится строка `Бот запущен`. Откройте своего бота в Telegram и отправьте `/start`. Остановить бота: `Ctrl + C`.

При следующих запусках достаточно перейти в папку, активировать окружение (`.venv\Scripts\Activate.ps1`) и выполнить `python main.py`.

## Установка и запуск на Linux

### 1. Установите Python

**Debian / Ubuntu:**
```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
python3 --version
```

**Fedora:** `sudo dnf install -y python3 python3-pip`
**Arch:** `sudo pacman -S python python-pip`

Нужна версия **3.11 или новее**. Если в вашем дистрибутиве Python старее, установите свежий через `pyenv` или репозиторий дистрибутива.

### 2. Скачайте проект

```bash
git clone <адрес-вашего-репозитория> tg_bot
cd tg_bot
```
Или распакуйте архив: `unzip tg_bot_shop.zip && cd tg_bot`.

### 3. Создайте виртуальное окружение и установите зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 4. Создайте файл `.env`

```bash
cp .env.example .env
nano .env
```
Заполните значения (см. [таблицу переменных](#настройка-env-все-переменные)). В `nano` сохранить — `Ctrl + O`, `Enter`, выйти — `Ctrl + X`.

### 5. Запустите бота

```bash
python main.py
```

Увидите `Бот запущен` — можно писать боту `/start`. Остановка: `Ctrl + C`. Чтобы бот работал постоянно, см. [запуск в фоне](#запуск-в-фоне-на-linux).

## Настройка `.env`: все переменные

Файл `.env` хранит секретные настройки. **Никогда не публикуйте его** и не отправляйте другим людям. После любого изменения `.env` бота нужно **перезапустить**.

| Переменная | Обязательная | Значение по умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | ✅ да | — | Токен вашего бота от @BotFather |
| `ADMIN_IDS` | ✅ да | пусто | Telegram ID администраторов через запятую |
| `SUPPORT_USERNAME` | нет | пусто | Username поддержки для кнопки в «Помощь» |
| `DB_PATH` | нет | `data/bot.db` | Путь к файлу базы данных SQLite |
| `LOG_LEVEL` | нет | `INFO` | Подробность логов |
| `CRYPTOBOT_TOKEN` | нет | пусто | Токен CryptoBot (запасной источник) |
| `CRYPTOBOT_TESTNET` | нет | `false` | Тестовый режим CryptoBot |
| `INVOICE_TTL_SECONDS` | нет | `1800` | Время жизни счёта в секундах |

### `BOT_TOKEN` — токен бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте имя бота (любое, например «Мой магазин») и username (должен заканчиваться на `bot`, например `my_shop_bot`).
3. BotFather пришлёт токен вида `123456789:AAFxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. Скопируйте его целиком.

```env
BOT_TOKEN=123456789:AAFxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Токен — это пароль от бота. Если он попал в чужие руки, отправьте BotFather `/revoke`, выберите бота и получите новый.

### `ADMIN_IDS` — кто является администратором

Это числовые Telegram ID людей, которым доступна команда `/admin`.

1. Откройте [@userinfobot](https://t.me/userinfobot) и отправьте любое сообщение — он ответит вашим ID (число вроде `123456789`).
   *Свой ID также показан в вашем боте: «👤 Профиль» → «🆔 ID».*
2. Впишите его в `.env`. Несколько администраторов — через запятую (пробелы допустимы):

```env
ADMIN_IDS=123456789
ADMIN_IDS=123456789,987654321
```

Если оставить поле пустым, администраторов не будет, и `/admin` не откроется ни у кого.

### `SUPPORT_USERNAME` — поддержка

Username аккаунта, куда будут писать покупатели. С символом `@` или без — неважно. Кнопка `👨‍💻 Написать в поддержку` и строка «Поддержка: @…» показываются **только в разделе «Помощь»**.

```env
SUPPORT_USERNAME=@my_support
```

> ⚠️ В файле `.env.example` стоит пример значения. **Замените его на свой username**, иначе покупатели будут писать не вам. Если оставить поле пустым, кнопка поддержки просто не появится.

### `DB_PATH` — файл базы данных

Бот хранит категории, товары, заказы, балансы и настройки в одном файле SQLite. По умолчанию это `data/bot.db` внутри папки проекта. Папку и файл бот создаёт сам при первом запуске.

Для резервной копии остановите бота и скопируйте этот файл. **В базе лежат ваши товары в открытом виде** — не публикуйте её и не добавляйте в Git (в `.gitignore` она уже исключена).

### `LOG_LEVEL` — уровень логов

Допустимые значения: `DEBUG` (максимум подробностей), `INFO` (обычный режим), `WARNING`, `ERROR`. Если не уверены — оставьте `INFO`.

### `CRYPTOBOT_TOKEN` — токен CryptoBot

Нужен для приёма оплаты и пополнения баланса.

**Где взять:**
1. Откройте [@CryptoBot](https://t.me/CryptoBot).
2. Перейдите в **Crypto Pay** → **Create App** (создать приложение).
3. Задайте название и откройте созданное приложение — там будет **API Token** вида `12345:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

*(Названия пунктов в CryptoBot могут немного отличаться — ищите раздел Crypto Pay / «Мои приложения».)*

**Два способа задать токен — выберите любой:**

- **Через админ-панель** (удобнее): `/admin` → `🔐 Настроить CryptoBot` → отправьте токен. Бот проверит его, сохранит в базу данных и удалит ваше сообщение с токеном.
- **Через `.env`**: впишите в `CRYPTOBOT_TOKEN`. Этот способ удобен для автоматического развёртывания.

Если токен есть и там, и там, **приоритет у токена из админки** (из базы данных). Значение из `.env` используется, только когда в базе токена нет. Экран «Настроить CryptoBot» показывает, откуда сейчас берётся токен.

### `CRYPTOBOT_TESTNET` — тестовый режим CryptoBot

У CryptoBot две **полностью отдельные** сети, и токены между ними не взаимозаменяемы:

| Значение | Режим | Где брать токен | Деньги |
|---|---|---|---|
| `false` | Боевой (mainnet) | [@CryptoBot](https://t.me/CryptoBot) | Реальные |
| `true` | Тестовый (testnet) | [@CryptoTestnetBot](https://t.me/CryptoTestnetBot) | Тестовые, ничего не тратится |

**Рекомендация:** сначала проверьте весь сценарий покупки в тестовом режиме (`true` + токен из @CryptoTestnetBot), и только потом переходите на боевой (`false` + токен из @CryptoBot).

Если указать токен не от той сети, при сохранении в админке вы увидите ошибку: *«Ошибка API. Если токен из @CryptoBot — выключите CRYPTOBOT_TESTNET в .env. Если из @CryptoTestnetBot — включите.»* Измените переменную и **перезапустите бота**.

В значении поддерживаются `true`, `1`, `yes` (без учёта регистра) — всё остальное считается `false`.

### `INVOICE_TTL_SECONDS` — срок жизни счёта

Сколько секунд покупатель может оплатить выставленный счёт. По умолчанию `1800` (30 минут). Просроченный счёт оплатить нельзя — покупателю придётся оформить заказ заново.

## Первый запуск: чек-лист

1. Запустите бота и отправьте ему `/start` со своего аккаунта.
2. Отправьте `/admin`. Если бот не отвечает, проверьте, что ваш ID указан в `ADMIN_IDS` и бот перезапущен.
3. **Подключите CryptoBot**: `🔐 Настроить CryptoBot` → отправьте токен (рекомендуется начать с testnet).
4. **Создайте категорию**: `➕ Добавить категорию` → введите название.
5. **Добавьте товар**: `📦 Добавить товар` → выберите категорию → `🆕 Создать новый товар` → название → цена в рублях → содержимое.
6. Нажмите `🏠 В меню магазина` и пройдите путь покупателя: каталог → товар → количество → оплата → получение файла.
7. Когда всё работает, переключитесь на боевой режим (`CRYPTOBOT_TESTNET=false`, боевой токен) и перезапустите бота.

## Как работает оплата

- Цены хранятся и показываются **в рублях**. Счёт в CryptoBot выставляется в рублях, а покупатель платит в любой доступной криптовалюте по курсу на момент оплаты.
- ⚠️ **Оплата не определяется автоматически.** После оплаты покупатель возвращается в бот и нажимает **«🔄 Проверить оплату»** — тогда бот проверяет счёт в CryptoBot и выдаёт товар. Кнопка остаётся в сообщении со счётом, пока счёт действителен.
- Если за время оплаты на складе стало меньше товара, чем куплено, **вся оплаченная сумма зачисляется на баланс** покупателя, и он может купить заново нужное количество.
- Если у покупателя списались деньги, а товар не пришёл, откройте в админке `💰 Баланс пользователя`, введите его ID (он виден в его профиле), посмотрите историю платежей и при необходимости **выдайте сумму на баланс** — с подтверждением, покупатель получит уведомление.
- **Баланс** пополняется самим покупателем через CryptoBot (в профиле) либо вручную администратором. Тратится на любые покупки.
- **Прибыль** в статистике — это сумма оплаченных заказов (выручка). Себестоимость бот не учитывает.

## Как добавлять товары

Каждая **строка** содержимого — это **одна единица товара**. Покупатель, купивший 3 штуки, получит 3 строки.

Пример для продажи аккаунтов (формат строки — любой, какой вам удобен):

```
email1@mail.com;password1;cookie1
email2@mail.com;password2;cookie2
email3@mail.com;password3;cookie3
```

Данные можно отправить двумя способами:

- **Текстом** — вставьте строки в сообщение (подходит для небольших партий).
- **Файлом `.txt`** (до 1 МБ, кодировки UTF-8 и Windows-1251) — удобно для сотен позиций, Telegram не разобьёт длинное сообщение на части.

**Пополнение** уже существующего товара: `📦 Добавить товар` → категория → `📦 Пополнить: Название (Цена)` → отправьте новые строки. Название и цену вводить заново не нужно. Товары с одинаковым названием и ценой в одной категории объединяются в один общий остаток.

> ℹ️ Данные в файле заказа записываются без изменения регистра: пароли, cookie и ключи часто чувствительны к заглавным и строчным буквам. Заголовки файла (`ЗАКАЗ`, `ТОВАР`, `ДАННЫЕ`) пишутся заглавными. Если вам нужно, чтобы и данные приводились к верхнему регистру, поменяйте `UPPERCASE_FILE_DATA = False` на `True` в начале `handlers/user.py`.

## Запуск в фоне на Linux

Если закрыть терминал, бот остановится. Чтобы он работал постоянно и сам перезапускался, настройте службу **systemd**.

1. Положите проект, например, в `/opt/tg_bot`, создайте там окружение и установите зависимости (как в разделе про Linux).
2. Создайте файл службы `sudo nano /etc/systemd/system/tg_bot.service`:

```ini
[Unit]
Description=Telegram shop bot
After=network-online.target
Wants=network-online.target

[Service]
User=botuser
WorkingDirectory=/opt/tg_bot
ExecStart=/opt/tg_bot/.venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Замените `botuser` на имя вашего пользователя (не `root`, если это возможно).

3. Включите и запустите:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tg_bot
```

4. Полезные команды:

```bash
sudo systemctl status tg_bot      # состояние
sudo systemctl restart tg_bot     # перезапуск (после изменения .env)
journalctl -u tg_bot -f           # логи в реальном времени
```

Для быстрого запуска «на потом» можно также воспользоваться `tmux` или `screen`.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `python` не найден (Windows) | Переустановите Python с галочкой «Add python.exe to PATH» или используйте команду `py` вместо `python` |
| `python` не найден (Linux) | Используйте `python3` вместо `python` (вне виртуального окружения) |
| `ModuleNotFoundError: No module named 'aiogram'` | Не активировано окружение или не установлены зависимости: активируйте `.venv` и выполните `pip install -r requirements.txt` |
| `RuntimeError: BOT_TOKEN не задан` | Файла `.env` нет, он лежит не в папке проекта или называется `.env.txt` |
| `TelegramUnauthorizedError` / `Unauthorized` | Неверный `BOT_TOKEN`: скопируйте токен у @BotFather заново, без пробелов и кавычек |
| `TelegramConflictError: terminated by other getUpdates` | Бот запущен дважды (на другом компьютере, в другом окне терминала или в службе). Оставьте один экземпляр |
| `/admin` не отвечает | Ваш ID не указан в `ADMIN_IDS` или после правки `.env` бот не перезапущен |
| «Токен не прошёл проверку», HTTP 401 | Токен не от той сети: сверьтесь с таблицей в разделе про `CRYPTOBOT_TESTNET` и перезапустите бота |
| «Оплата через CryptoBot временно недоступна» | Токен CryptoBot не задан ни в админке, ни в `.env` |
| Оплатил, а товар не пришёл | Нажмите «🔄 Проверить оплату» в сообщении со счётом; если не помогло — напишите в поддержку, администратор может выдать сумму на баланс |
| Изменил `.env`, но ничего не поменялось | Настройки читаются один раз при старте — перезапустите бота |

Для диагностики можно поставить `LOG_LEVEL=DEBUG` — в консоль попадёт больше подробностей (токены в логи не выводятся).

## Безопасность

- **Не публикуйте** `.env` и папку `data/` (они уже в `.gitignore`). Перед отправкой проекта в открытый репозиторий убедитесь, что в нём нет ваших токенов.
- Если токен случайно опубликован — немедленно перевыпустите его: у BotFather командой `/revoke`, а токен CryptoBot — в настройках приложения Crypto Pay.
- В базе данных товары хранятся в открытом виде. Ограничьте доступ к файлу `data/bot.db` и делайте его резервные копии.
- Администраторами становятся только ID из `ADMIN_IDS`: проверка выполняется на стороне бота для каждого действия в админ-панели.
- Диалоги (ввод суммы, добавление товара и т. п.) хранятся в памяти: после перезапуска бота незавершённые действия сбрасываются. Данные магазина при этом сохраняются.
